# 实施计划：聊天替换模型与静态航迹

## 文件职责

- `TacticalDemo/Source/TacticalDemo/ScenarioConfig.h`：场景单位组与航点值结构。
- `ScenarioConfigLoader.cpp`：严格校验航点 JSON。
- `EquipmentLibrary.h/.cpp`：读取已注册模型目录、验证 ID 与类别、支持严格候选资源解析。
- `ChatProtocol.h/.cpp`：解析模型 ID/航迹修改，保留未修改配置，扩展场景请求识别和 Qwen 指令。
- `DemoControlWidget.cpp`：向 Qwen 提供模型目录、校验候选模型、展示可用指令和航点状态，应用候选时启用严格模型检查。
- `DemoScenarioManager.h/.cpp`：事务性应用严格候选场景并重绘/清理静态航迹线。
- `Tests/ScenarioTests.cpp`、`Tests/ChatTests.cpp`、`Tests/SceneTests.cpp`：围绕配置、协议和场景可见结果添加回归测试。
- `README.md`、`PROJECT_FRAMEWORK.md`、`PROJECT_MAP.md`、`PROJECT_STATUS.md`：说明当前静态航迹和注册模型能力，移除聊天颜色修改需求/操作说明。

## 任务 1：航点配置解析

1. 先添加配置自动化测试：合法两点航迹解析到米制值，空数组可清除，单点、33 点、缺轴、字符串、无穷/越界坐标被拒绝且输出配置不变。
2. 运行对应 UE 自动化测试，确认新增用例因当前不支持 `route` 而失败。
3. 增加 `RouteMeters` 并实现严格解析，移除将 route 当作忽略字段的逻辑。
4. 重跑对应测试。

## 任务 2：模型设备库与聊天协议

1. 先添加协议用例：请求分类包含替换模型/航迹，提问句不误入修改；update 保留其他组和未提字段；set 支持合法模型 ID 与航迹；非法类型/字段/航迹被拒绝。
2. 运行测试确认新场景能力用例失败。
3. 添加设备库目录与注册验证；扩展 create/update/full-scenario 白名单及合并；将指令示例限定为库内模型，航迹仅保存/显示，不移动单位。
4. 运行协议测试并检查所有错误分支。

## 任务 3：事务应用与地图航迹显示

1. 先添加场景测试：静态航点折线生成；应用已注册的不同模型成功；未知 ID/不匹配类型/资源不可加载失败并保留原 Actor 与旧航迹；清场删除航迹。
2. 运行用例确认失败。
3. 在管理器中使用 `ULineBatchComponent` 绘制米制航点转换后的静态折线，准备/验证所有候选后再替换原场景；聊天候选采取严格模型加载，原场景保留现有回退行为。
4. 运行场景用例。

## 任务 4：窗口、文档和整体验证

1. 更新窗口帮助示例与单位详情，展示替换模型、静态坐标、设置/清除航迹；删除聊天颜色修改内容。
2. 更新项目阶段说明和 README 的能力边界，明确静态航迹不自动移动单位。
3. 执行 `Scripts/Validate.ps1`、`Scripts/Build.ps1`、`Scripts/Test.ps1`；若本机 Qwen 服务已在线，再运行扩展后的真实 Qwen 集成测试。
4. 检查工作区差异、测试摘要、日志以及真实 Qwen 请求结果，记录未能执行的验证和原因。

## 完成标准

聊天能生成并手动应用模型替换、静态位置、静态航迹候选；地图显示航线且单位不会自行移动；非法模型/航点不改变旧场景；聊天颜色操作不再被提示或支持；构建和自动化测试结果有可复核记录。
