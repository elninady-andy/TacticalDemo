# 聊天替换模型与静态航迹设计

## 目标

扩展 TacticalDemo 的自然语言配置流程，使用户可以选择设备库中已登记的模型、调整单位组静态位置、配置静态航点并在地图上查看航迹。删除聊天中修改阵营显示颜色的能力、指令范例和帮助文案；保留红蓝阵营现有外观差异。

## 已确定的约束

- 航迹只是配置和场景显示数据，不驱动单位移动，也不包含开始/暂停/速度控制。
- 单位位置仍是独立的静态坐标修改；航迹以单位组为归属，组内单位共享一条航线。
- 模型只能选 `EquipmentLibrary.json` 注册且类型匹配的 `modelId`；不接收任意文件路径，不修改设备库。
- 回复仍先成为候选配置，由用户手动应用。模型 ID、资产或场景校验失败时保留旧场景。
- 航点以米保存；每组允许 0 或 2–32 个航点。空数组清除航迹。坐标必须有限且在 ±1,000,000 米范围内。
- 红蓝阵营原有模型/材质视觉区分不变；聊天不可修改显示颜色。

## 数据格式

单位组可选字段 `route` 是点数组，每点包含有限数值 `x`、`y`、`z`（米）。例如：

```json
"route": [{"x":0,"y":0,"z":5},{"x":20,"y":10,"z":5}]
```

静态位置继续使用 `position`。创建命令可选给出 `modelId` 和 `route`；更新命令在 `set` 中支持 `modelId`、`route`、现有数量/阵营/位置/间距字段。C++ 合并更新到当前场景快照，确保未提及字段保留。

## 组件与流程

- `FDemoUnitConfig` 保存航点，`FScenarioConfigLoader` 负责航点结构、数量、范围和有限数校验。
- `FEquipmentLibrary` 提供注册模型目录与指定模型 ID/类型的校验。模型目录随场景请求提供给 Qwen；修改后的 ID 在成为候选前校验。候选应用时要求资源确实能加载，原始磁盘场景沿用现有默认模型回退策略。
- `FDemoChatProtocol` 解析创建、更新和完整场景输出；将模型替换、静态位置和航迹自然语言请求识别为场景请求。未支持字段继续拒绝，不允许模型声称执行运动。
- `ADemoScenarioManager` 在候选场景事务应用时生成单位，并用静态线批组件画出共享航迹。新场景验证和单位创建成功后才替换旧单位与航迹；清场/重载同步清理旧线。航迹线不参与单位变换。
- 对话窗口显示当前单位组航点数量及受支持指令示例，不提供颜色操作。

## 安全与错误处理

协议拒绝非法字段、非字符串/未注册/类型不符的模型 ID、航点不足/超限/非有限值和超过坐标范围的轨迹。候选阶段和应用阶段均报告具体失败，旧画面不变。Qwen 不可写任意路径或设备库文件。

## 验收

自动化测试覆盖：合法/空/非法航迹解析，航点数和坐标边界，静态航迹绘制和清场，更新位置不改高度/间距，替换已注册模型，拒绝未知或类型不符模型，失败时保留旧单位/航迹，聊天提示不包含颜色修改能力。运行 UE 构建和完整自动化套件；本机 Qwen 的替换模型与航点自然语言集成测试若服务在线则执行，并记录实际验证结果。
